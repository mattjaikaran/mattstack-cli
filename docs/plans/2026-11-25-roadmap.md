# mattstack roadmap: keep growing Django/React codebases in line

Date: 2026-11-25
Status: Accepted 2026-11-25. Decisions for read replicas (S-CLI-35) and architecture
contracts (S-CLI-42) are recorded; both specs are READY.
Audit base: `origin/main` of each repo in `~/dev/boilerplates`, read 2026-11-25

## Problem

mattstack scaffolds projects well, but large codebases drift after the
scaffold. The boilerplates also drift from each other:

- `django-ninja-boilerplate` runs 22 gates (safe-migration lint, schema
  parity, journeys, agent docs, `check --deploy`). Other backends run far
  fewer. A project's guarantees depend on which boilerplate it came from.
- Agent instructions are split across three layouts (see "Agent-agnostic
  layout"). Five repos' own checkers *enforce* `.claude/skills`, so the
  target layout fails their gates today.
- mattstack cannot see or update the boilerplates it clones. Every
  cross-repo change is manual.

## Themes

### 1. Agent-agnostic layout (do first; unblocks everything)

Target, for every repo and every generated project:

- `AGENTS.md` is the only instruction file. No `CLAUDE.md` and no other
  harness adapter (`.cursorrules`, `.cursor/rules`, `GEMINI.md`).
- Skills live in `.agents/skills/<name>/SKILL.md` with `name` and
  `description` frontmatter. No tracked `.claude/` directory.
- Harness-local state (`.claude/`, `.cursor/`) is gitignored.
- The repo's agent-docs checker enforces all three rules.

Current state on `origin/main`:

`.agents/skills/` the target needs the same depth, so it stays
`../../../node_modules/...`.

mattstack-cli itself is not compliant: root `CLAUDE.md`,
`post_processors/consolidate.py` keeps `.claude/skills`,
`commands/context_builders.py` reports `claude_md`, `commands/upgrade.py`
skips `CLAUDE.md`, `commands/rules.py` writes `.cursor/.cursorrules`, and
`templates/root_gitignore.py` ignores only `.claude/settings.local.json`.

### 2. Fleet: mattstack delegates to its boilerplates

New `mattstack fleet` group (registry = `REPO_URLS` plus B2B repos):

- `fleet list`: repos, default branch, local path, behind/ahead/dirty.
- `fleet check`: run conformance rules (agent layout, required gates,
  Python/Node pins) against each repo's `origin/main` without cloning.
  Output a parity matrix; `--json` for agents.
- `fleet issue --template <file> --repos <glob>`: open one refined issue per
  repo from a template, skip repos that already have it (title match),
  label `fleet`, link back to a tracking issue here.

### 3. Postgres: stability under growth

- `audit migrations`: static safe-migration rules for every Django backend
  (non-null column without default, `AddIndex` without `Concurrently`,
  `RunPython` without reverse, column rename/drop in one deploy, merge
  migrations). Reuse django-ninja's policy; ship it in the other backends.
- `db doctor`: live checks via `psql`: `pg_stat_statements` top queries,
  unindexed foreign keys, unused and duplicate indexes, table bloat,
  long-running transactions, connections vs `max_connections`.
- Query-count guard: generated tests use `assertNumQueries` around list
  endpoints so N+1 regressions fail tests.

### 4. Scaling: vertical and horizontal

- Vertical: `db tune --memory 8GB --cpus 4` writes a reviewed
  `postgresql.conf` fragment (pgtune rules) for Compose and k8s.
- Horizontal, app tier: `audit scale` flags state that breaks with more than
  one replica: `LocMemCache`, file sessions, local `MEDIA_ROOT` without S3,
  in-process schedulers, missing health endpoints.
- Horizontal, DB tier: `add pgbouncer` (transaction pooling; sets
  `DISABLE_SERVER_SIDE_CURSORS` and `CONN_MAX_AGE=0`) and `add read-replica`
  (router plus settings; django-ninja ROADMAP 4.24 already wants this).

### 5. Vector and graph

- Fix `init --graph age`: build an image with AGE and pgvector
  (`commands/init_runtime.py` rejects it today).
- `generate embedding <Model> --dims 1536`: `VectorField`, HNSW index
  migration, and a search service, following
  `core/ai/models/document.py` in django-ninja.
- `audit vectors`: vector columns without an ANN index, dimension mismatch
  between the configured embedding model and the column, pgvector version.
- `health --live` covers Qdrant and Neo4j when selected.

### 6. Standards that ratchet

- `audit --baseline`: record current findings; fail only on new ones. This
  lets strict rules land in big codebases without a cleanup project first.
- `sync check --breaking`: diff the OpenAPI spec against the base branch;
  fail on removed fields, narrowed types, and new required inputs.
- Architecture contracts in generated projects: import-linter layers for
  Django apps, dependency-cruiser boundaries for React features.
- `adr new <title>` writes `docs/adr/NNNN-title.md`.

## Decisions (2026-11-25)

- `CLAUDE.md` must not exist in any repo, including this one. The
  contract is in [docs/agent-layout.md](../agent-layout.md).
- Clean cutover: `rules sync` (per-harness adapters) and the `claude`
  context format are deleted, not deprecated. This replaces the "regenerate
  harness adapters" goal in
  [2026-08-12-control-plane-design.md](2026-08-12-control-plane-design.md);
  `fleet check` enforces the layout contract instead.
- Specs add no files under `tests/` and do not run pytest (agent-run
  executor rule). Acceptance rows run the CLI against temporary fixtures.
- Boilerplate tickets live in each boilerplate's issue tracker and link to
  one tracking issue in this repo. They are not S-CLI specs.
- New cross-repo checks (migrations, vectors, scale, OpenAPI breaking
  changes) are Gauntlet candidates. Move them there when Gauntlet ships.
- django-ninja already gates migrations, architecture, and OpenAPI drift,
  and ships k3s and Helm manifests. CLI specs cover only what it lacks.
- Read replicas (S-CLI-35): `mattstack add read-replica` adds an opt-in
  Compose streaming replica only. The router and `DATABASE_REPLICA_URL` wiring
  are a django-ninja issue (django-ninja-boilerplate #96). Replicas are never
  default-on.
- Architecture contracts (S-CLI-42): `audit --type architecture` is opt-in. It
  warns (never errors) when a generated component has no architecture gate.
  It depends on S-CLI-29 for the opt-in mechanism.

## Ticket rules (for small models)

Every issue is one vertical slice that a small model can finish and that
passes review the first time:

- Size `S` (≤8 files, ≤300 changed lines) by default; `M` only when it
  cannot be split.
- Sections: Goal, Context (file:line citations at a named commit), Files
  owned (exhaustive), Steps, Acceptance (commands with expected output),
  Out of scope, Stop conditions (when to stop and ask instead).
- No design decisions left open. Open questions get the `needs-human`
  label and are not claimable.
- Labels: `size:S|M`, `spec`, area (`agent-docs`, `fleet`, `db`, ...).
